## Additional specific behavior gaps found

- VMSS quiesced snapshots: upstream NewPolicySnapshotTypePage supports snapshot_with_quiesce; local VMSS validation permits only snapshot/checkpoint.
- VMSS minute validation: upstream hourly choices are 0/15/30/45 (`NewPolicySnapshotFrequencyPage.resx:207–217`), and daily/weekly/hourly serialization calls `HelpersGUI.RoundToNearestQuarter` before writing `Schedule["min"]`. Local `validate_vmss_fields` accepts any minute 0–59, and `schedule_map` serializes it unchanged. Parent live audit reported daily minute 7 rejected by the host with INVALID_VALUE; the source mismatch is independently confirmed here. Root owns the live logs and final verification of a valid minute.
- VMSS schedule time handling: original NewPolicySnapshotFrequencyPage reads coordinator local time and accounts for client/server timezone; native raw hour/minute editing does not reproduce this workflow.
- NewNetworkWizard type gating: original NetWTypeSelect applies server/version/license/NIC eligibility and hides CHIN on Stockholm+; native type entrypoints do not reproduce those original gates.

## Verification boundary

Compared owning wizard constructors, navigation/finish methods, selected values, eligibility checks and command dispatch against native dialog/state/action/worker/core methods. Framework helpers are mapped to native architectural responsibilities without pretending that source-class equality is feature parity. Missing high-level workflows remain missing even when a shared primitive exists.

Key native anchors: `native/src/views/dialogs.rs` (VM edit, network, HA, VMSS and action review modals), `native/src/state.rs` (dialog/selection/load state), `native/src/views/sidebar.rs` and `inventory.rs` (menus), `crates/xen-core/src/vmss.rs` (snapshot types/schedules), `network.rs` (network operations), `pool_actions.rs` (HA/WLB operations), `dr.rs` (DR_task primitive only).
