## Status report evidence and reachability

Upstream has real report-collection code, not just labels:

- `StatusReport/ClientSideStatusReportAction.cs`: copies client/rotated logs and writes coordinator/supporter information and client metadata.
- `Host/SingleHostStatusAction.cs::SingleHostStatusReportAction`: creates a task and downloads the server diagnostic tar via `HTTP_actions.get_system_status` using selected capability keys.
- `StatusReport/ZipStatusReportAction.cs`: sanitizes/extracts raw server tars and packages them with other files into ZIP, supporting cancellation and cleanup.
- `StatusReport/StatusReportAction.cs`: abstract report-specific state/path/time/cancel model.

Repository-wide C# search for `ClientSideStatusReportAction`, `ZipStatusReportAction` and `SingleHostStatusReportAction` found declarations and constructors only, **no call sites that construct them**. Therefore this audit verifies source capabilities but cannot claim an exposed server-status-report wizard in this pinned upstream UI. Local `native/src` and `crates/xen-core/src` have no matching report generation/download/ZIP flow either. A health-check screen is not a downloadable support bundle.
